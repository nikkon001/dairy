# 🌸 Мой дневник

Личный дневник в браузере. Записи сохраняются отдельными `.md` файлами в приватный репозиторий на GitHub.

## Что умеет

- Заметки с заголовком, датой, тегами и настроением дня
- Недельный планер: сетка по часам и дела на каждый день
- Трекинг проектов: сроки, этапы и линия прогресса
- Отдельный список задач с галочками и прогрессом — живёт сам по себе, не привязан к дате
- Планер и редактор записи сворачиваются, чтобы не мешать друг другу
- Одна фотография на запись — сжимается в браузере и хранится в репозитории
- Поиск по тексту и фильтр по тегам
- Календарь месяца — иконка настроения и число записей на каждом дне
- Статистика месяца — сколько записей, сколько дней закрыто, какие настроения и теги преобладали
- Работает с телефона, планшета и компьютера — записи везде одни и те же
- Копия хранится в браузере, так что писать можно и без интернета
- Кнопка «Скачать все записи», если захочется забрать всё с собой

---

## Как это устроено

Два репозитория, и это важно:

| | Что внутри | Приватность |
|---|---|---|
| **Репозиторий с приложением** | только `index.html` | **публичный** |
| **Репозиторий с записями** | папка `entries/` | **приватный** |

Приложение не хранит записи внутри себя. Каждый раз при открытии оно идёт в GitHub и забирает их оттуда живьём — по твоему токену. Поэтому публичная страничка безопасна: тот, кто откроет ссылку без токена, увидит пустой дневник и форму настроек, и больше ничего.

---

## Шаг 1. Репозиторий с приложением (публичный)

1. На GitHub → **New repository** → назови, например, `diary-app`
2. Оставь **Public** → **Create repository**
3. **Add file** → **Upload files** → перетащи `index.html` → **Commit changes**
4. **Settings** → слева **Pages** → *Build and deployment*:
   - Source: **Deploy from a branch**
   - Branch: **main**, папка **/ (root)** → **Save**
5. Через 1–2 минуты дневник откроется по адресу
   `https://ТВОЙ-НИК.github.io/diary-app/`

Сохрани эту ссылку в закладки на телефоне. Больше к этому репозиторию возвращаться не придётся.

## Шаг 2. Репозиторий с записями (приватный)

1. На GitHub → **New repository** → назови, например, `diary-entries`
2. Выбери **Private** ✅ и поставь галочку **Add a README file** → **Create repository**

Папку `entries/` создавать не нужно — дневник создаст её сам при первой записи.

## Шаг 3. Токен

Токен — это ключ, которым приложение записывает файлы в приватный репозиторий.

1. Открой [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new)
   Проверь, что вверху написано **Fine-grained token**, а не *Tokens (classic)* — у классических токенов список прав совсем другой.
2. **Token name** — любое, например `Дневник`
3. **Expiration** — срок жизни. Когда истечёт, токен придётся выпустить заново
4. **Repository access** → **Only select repositories** → выбери `diary-entries`
5. Прокрути до **Permissions** → раздел **Repository permissions**.
   Это длинный список по алфавиту: Actions, Administration, … Найди в нём строку **Contents** и справа в выпадающем списке выбери **Read and write**.
   Строка **Metadata: Read-only** добавится сама — так и должно быть.
6. Внизу → **Generate token**
7. Скопируй токен сразу — GitHub показывает его один раз

> Не находится **Contents**? Значит, ты либо на странице классических токенов, либо ещё не выбрала репозиторий на шаге 4 — список прав появляется только после этого.

## Шаг 4. Подключить

Открой дневник по ссылке из шага 1 → ⚙️ **Настройки**:

- **Владелец** — твой ник на GitHub
- **Репозиторий** — `diary-entries` (приватный, из шага 2)
- **Ветка** — `main`
- **Папка для записей** — `entries`
- **Personal access token** — вставь токен из шага 3

**Сохранить и синхронизировать** — готово 🎉

Токен хранится только в этом браузере (localStorage) и уходит напрямую в GitHub — больше никуда. На новом устройстве настройки нужно ввести один раз.

## Формат записи

Каждая запись — файл `entries/2026-08-16-nazvanie.md`:

```markdown
---
title: Название записи
date: 2026-08-16
mood: joy
tags: мысли, книги
---

# Название записи

Текст записи…
```

Читаются прямо на GitHub, так что дневник можно листать и без приложения. Можно даже написать запись руками через **Add file** — дневник её подхватит.

Настроения: `joy` — радость, `calm` — спокойствие, `energy` — энергия, `cozy` — уют, `sad` — грусть.

## Задачи

Список задач лежит отдельно от записей — в файле `tasks.md` в корне приватного репозитория:

```markdown
# Задачи

- [x] Купить хлеб
- [ ] Позвонить маме
```

Это обычные markdown-чекбоксы, поэтому на GitHub они выглядят как настоящие галочки и их можно отмечать прямо там — дневник подхватит изменения при следующей загрузке.

Правки копятся пару секунд и уходят одним коммитом, чтобы история не засорялась. Выполненные задачи остаются зачёркнутыми, пока не нажмёшь «Убрать сделанные».

## Планер

Неделя лежит в своём файле — `planner/2026-08-17.md`, по дате понедельника:

```markdown
# Планер · 17–23 августа 2026

## Пн · 2026-08-17

**09:00** Созвон с командой
**14:00** Зал

- [ ] Оплатить счёт
```

Сетка охватывает часы с 06:00 до 23:00 и прокручивается внутри себя, а под ней у каждого дня свой список дел. Пустые дни в файл не попадают. Стрелки листают недели, «Текущая неделя» возвращает на сегодня.

## Проекты

Лежат в файле `projects.md` в корне репозитория:

```markdown
# Проекты

## Ремонт кухни

Сроки: 2026-08-01 — 2026-10-15

- [x] Смета
- [ ] Закупка
- [ ] Работы
```

У каждого проекта своя линия, разбитая на этапы. Пустой этап — красный контур, закрытый — сплошная красная заливка. Когда закрыты все, в конце линии появляется звезда, а проект уходит в серый и уползает вниз по смыслу — но остаётся на виду.

Если дедлайн близко (неделя или меньше) — рядом появится счётчик дней, а если срок прошёл — красная пометка «просрочен». У завершённых проектов дедлайн не показывается.

## Фотографии

Одно фото на запись. Перед отправкой оно уменьшается до 1400 px по длинной стороне и сжимается в JPEG — обычно выходит 100–300 КБ, так что репозиторий не разрастётся.

Фото лежат отдельными файлами в папке `media/` и подписаны так же, как запись:
`entries/2026-08-16-more.md` → `media/2026-08-16-more.jpg`. В самой записи стоит обычная ссылка на картинку, поэтому фото видно и при просмотре на GitHub.

В списке записей иконка камеры значит, что фото есть. Само изображение подгружается только когда открываешь запись — чтобы дневник не тормозил.

> Снимаешь на айфон? Если файл в формате HEIC не открывается, выбери его через «Фотоплёнку» — iOS отдаст JPEG сама. Либо в настройках айфона: Камера → Форматы → **Наиболее совместимый**.

## Мелочи

- Открыть `index.html` двойным щелчком на компьютере — работает точно так же
- `Ctrl/Cmd + S` — сохранить запись, `Esc` — закрыть настройки
- Иконка облака рядом с датой значит, что запись уже улетела в GitHub
- Если чужой человек откроет твою ссылку — он увидит пустой дневник. Записи без токена не подтягиваются
